# Life & Work TODO

仕事（サロン・AI事業）と生活（家庭など）の「やること」を1か所で管理できる、日本語のTODO Webアプリです。
スマホでも見やすい画面で、データは Googleスプレッドシートに保存されます。

GitHub リポジトリ: https://github.com/meg-unframe/python-todo-app

## 制作目的

サロンの仕事、AI事業、家庭のことなど、やることがいくつものメモやアプリに分かれていると、抜け漏れが起きやすくなります。
このアプリは、次のことを目的に作りました。

- 仕事と生活のやることを **1か所** にまとめて管理する
- 期日・カテゴリ・優先度で整理し、**今やるべきこと** がすぐ分かるようにする
- 毎週・毎月の決まった作業を **繰り返しTodo** にして、登録の手間を減らす
- **Googleカレンダー** や **LINE** と連携して、アプリを開かなくても予定と期限に気づけるようにする

## 今回追加した3つの機能

### 1. 繰り返しTodo（毎日・毎週・毎月）

登録・編集画面で「繰り返し」を **なし / 毎日 / 毎週 / 毎月** から選べます。
繰り返しのTodoには、一覧に「🔁 毎週」のようなバッジが付きます。

- 繰り返しのTodoを **完了にすると、次の回のTodoが自動で1件作られます**。
  - 毎日: 翌日 ／ 毎週: 7日後 ／ 毎月: 翌月の同じ日
  - その日が無い月は月末にします（例: 1月31日 → 2月28日 → 3月31日）。
  - 完了が遅れた場合は、今日以降の最初の回まで期日を進めます。
- 完了と未完了を何度切り替えても、次の回が重複して作られることはありません。
- 繰り返しにするには期日の入力が必要です。

### 2. Googleカレンダー連携

期日のあるTodoを登録すると、**Googleカレンダーのその日に終日の予定が自動で作られます**。
連携しているTodoには、一覧に「📅 カレンダー」のバッジが付きます。

| アプリでの操作 | カレンダーの予定 |
|---|---|
| 期日ありで登録 | 期日に終日の予定を作る（タイトル・内容を反映） |
| タイトルや期日を編集 | 予定も同じように変更する |
| 期日を消す | 予定を削除する |
| 完了にする | 予定のタイトルの先頭に「✅」を付ける（未完了に戻すと外す） |
| 繰り返しの次の回ができる | 次の回の予定も作る |
| Todoを削除 | 予定も削除する |

カレンダーとの通信に失敗しても Todo の保存は行い、画面に警告を表示します。
環境変数 `GOOGLE_CALENDAR_ID` を設定したときだけ動きます（設定しなければ、これまでどおりの動きです）。

### 3. LINE通知（今日・明日・期限切れ）

**未完了** のTodoのうち、次の3種類をまとめて **1通のLINEメッセージ** で知らせます。

- ⚠️ 期限切れのTodo
- 📅 今日が期日のTodo
- 🔜 明日が期日のTodo

完了済み・期日なし・明後日以降のTodoは送りません。
対象が1件もない日は、LINEを送らずに正常に終わります。
同じ日に2回呼ばれても、同じTodoを二重に送ることはありません（期限切れのTodoは、完了するまで毎日通知します）。

通知は、アプリの通知用URL（`POST /tasks/notify-due`）が呼ばれたときに送ります。
**定期実行サービス（例: cron-job.org）から毎朝8時に呼び出して使う想定** で作っています。

## ローカルでの起動手順

Mac のターミナルでの例です。

```bash
# 1. リポジトリを取得する
git clone https://github.com/meg-unframe/python-todo-app.git
cd python-todo-app

# 2. Python の仮想環境を作って有効にする
python3 -m venv .venv
source .venv/bin/activate

# 3. 必要なパッケージを入れる
pip install -r requirements-dev.txt

# 4. 設定ファイルを作る（見本をコピーして、中身を自分の値に書き換える）
cp .env.example .env

# 5. 起動する
flask --app app run --debug
```

ブラウザで http://127.0.0.1:5000 を開き、`.env` に設定したパスワードでログインします。

### Googleの設定なしで画面だけ試したい場合

`.env` で `STORAGE_BACKEND=memory` にすると、スプレッドシートを使わずに動かせます（データはアプリを止めると消えます）。
`SECRET_KEY` と `APP_PASSWORD`（8文字以上）だけは設定が必要です。

## 環境変数

設定は `.env` ファイル（または公開先の環境変数）に書きます。
**`.env` は Git で管理しない設定になっており、GitHub には公開されません。**
項目の見本は `.env.example` にあります（値は空欄かダミーです）。

| 名前 | 用途 | 必須 |
|---|---|---|
| `SECRET_KEY` | ログイン状態を守るための署名キー（長いランダムな値） | 必須 |
| `APP_PASSWORD` | ログイン用のパスワード（8文字以上） | 必須 |
| `STORAGE_BACKEND` | 保存先（`sheets` または `memory`） | 任意（既定は `sheets`） |
| `SPREADSHEET_ID` | 保存先のスプレッドシートのID | スプレッドシート保存のとき |
| `WORKSHEET_NAME` | シート名（無ければ自動で作る） | 任意（既定は `todos`） |
| `GOOGLE_APPLICATION_CREDENTIALS` | サービスアカウントの鍵ファイルの場所 | どちらか一方 |
| `GOOGLE_CREDENTIALS_JSON` | 鍵ファイルの中身（ファイルを置けないサーバー向け） | どちらか一方 |
| `APP_TIMEZONE` | 期限を判定するタイムゾーン | 任意（既定は `Asia/Tokyo`） |
| `SESSION_COOKIE_SECURE` | `1` でログインのCookieをHTTPS限定にする | 任意 |
| `GOOGLE_CALENDAR_ID` | 連携するGoogleカレンダーのID | カレンダー連携のとき |
| `LINE_CHANNEL_ACCESS_TOKEN` | LINE Messaging API のチャネルアクセストークン | LINE通知のとき |
| `LINE_USER_ID` | 通知を送る自分のLINEユーザーID | LINE通知のとき |
| `NOTIFY_TOKEN` | 通知用URLを呼ぶための秘密のトークン（32文字以上） | LINE通知のとき |
| `APP_BASE_URL` | LINEのメッセージに付けるアプリのURL | 任意 |

## GoogleカレンダーとLINE通知の仕組み

### 全体の流れ

```text
【Todoの操作】
ブラウザ（スマホ・PC）
  → Life & Work TODO（Flaskアプリ）
      → Googleスプレッドシート … Todoを保存する
      → Googleカレンダー     … 予定を作成・変更・削除する

【毎朝の通知】
定期実行サービス（例: cron-job.org、毎朝8時）
  → Life & Work TODO の POST /tasks/notify-due（秘密のトークンで認証）
      → LINE Messaging API → 自分のLINEに1通届く
```

### Googleカレンダー連携

1. アプリは **サービスアカウント**（アプリ専用のGoogleアカウント）でGoogleに接続します。スプレッドシートと同じ認証情報を使います。
2. 自分のGoogleカレンダーを、サービスアカウントのメールアドレスに **「予定の変更」権限で共有** しておきます。
3. Todoを登録・編集・完了・削除すると、アプリが Google Calendar API を呼んで予定を作成・更新・削除します。
4. 予定のIDはスプレッドシートの `calendar_event_id` 列に保存し、どのTodoがどの予定なのかを対応させています。

事前準備: Google Cloud で Calendar API を有効にし、カレンダーを共有して、そのカレンダーIDを `GOOGLE_CALENDAR_ID` に設定します。

### LINE通知

1. LINE Developers で **Messaging API チャネル**（LINE公式アカウント）を作り、自分のLINEで友だち追加します。
2. 定期実行サービスが、アプリの `POST /tasks/notify-due` を呼び出します。このとき、ヘッダー `Authorization: Bearer <NOTIFY_TOKEN>` で秘密のトークンを送ります。
3. アプリはトークンを確認したあと、期限切れ・今日・明日の未完了Todoを集め、LINE Messaging API の **push メッセージ** で1通にまとめて送ります。
4. 送ったTodoには、スプレッドシートの `notified_on` 列に送った日を記録し、同じ日の重複送信を防ぎます。

通知用URLの応答（結果）:

| 状況 | 応答 |
|---|---|
| 送信した | `200` `{"status": "sent", "count": 件数, ...}` |
| 対象がない（送らない） | `200` `{"status": "no_targets", "count": 0}` |
| トークンが無い・違う | `401` `{"status": "unauthorized"}` |
| GET など POST 以外で呼んだ | `405` |
| LINE の設定がない | `503` `{"status": "not_configured"}` |
| LINE API で失敗した | `502` `{"status": "line_error"}`（送った日は記録しないので、次回また送る） |

手動で試す場合の例（`<NOTIFY_TOKEN>` の部分は自分のトークンに置き換えます）:

```bash
curl -X POST -H "Authorization: Bearer <NOTIFY_TOKEN>" http://127.0.0.1:5000/tasks/notify-due
```

### スプレッドシートの列

1行目が見出し（ヘッダー）、2行目以降が1件ずつのTodoです。

`id, title, content, due_date, category, priority, completed, created_at, updated_at, repeat, series_id, calendar_event_id, notified_on`

今回の3機能で `repeat` 以降の4列を **末尾に追加** しました。
古いシートを使っている場合は、アプリが見出しに足りない列名だけを自動で書き足します。**既存のTodoのデータは書き換えません。**

## セキュリティ対策

| 対策 | 内容 |
|---|---|
| 秘密情報をコードに書かない | パスワード・鍵・トークンはすべて環境変数から読みます。`.env` と鍵ファイルは `.gitignore` で除外しており、GitHub には含まれていません |
| ログイン必須 | 全ページでパスワードログインが必要です。パスワードは一定時間で比較します |
| 総当たり対策 | ログインに5回続けて失敗すると、そのIPアドレスを15分間ロックします |
| 起動時のチェック | `SECRET_KEY` が未設定、または `APP_PASSWORD` が8文字未満だと起動しません |
| CSRF対策 | すべてのフォーム送信（POST）に確認用トークンを付けて検証します |
| Cookie の保護 | HttpOnly・SameSite=Lax を付けます。HTTPS 環境では Secure も付けられます |
| 外部サイトへの転送防止 | ログイン後の移動先は、同じサイトの中だけに限定します |
| 数式の実行防止 | スプレッドシートへは `RAW` で書き込み、`=` で始まる入力が数式として動かないようにします |
| 画面表示の安全性 | 入力内容は HTML としてエスケープして表示します |
| 操作は POST のみ | 完了の切り替え・削除・通知は POST でしか受け付けません |
| 通知用URLの認証 | 32文字以上の秘密のトークンで認証します。トークンが無い・違う・短い場合は常に拒否します |
| 最小限の権限 | Googleの権限はスプレッドシートとカレンダーの予定（`calendar.events`）だけです |
| 失敗時の安全性 | カレンダーやLINEで失敗しても Todo の保存は行います。エラーの記録にトークンは含めません |

## テスト

```bash
python -m pytest -v
```

**100件のテストがすべて成功** しています。

テストはメモリ保存と、偽物のスプレッドシート・カレンダー・LINE（本物の代わりに動く仕組み）を使って実行します。
そのため、Googleの認証情報やLINEのトークンは不要で、本物のカレンダーやLINEに接続することはありません。

主なテストの内容:

- 登録・一覧・編集・完了切替・削除・入力チェック・HTMLのエスケープ
- 期限切れ・今日の表示、期日順・優先度順、カテゴリの絞り込み
- ログイン（ロック、ログアウト、外部URLへの転送防止）、CSRF、Cookieの設定
- スプレッドシートへの保存（`RAW` での書き込み、古い見出しの自動拡張で既存データが変わらないこと）
- 繰り返し: 次の期日の計算（月末・うるう年・遅れて完了した場合）、次の回の作成と重複防止
- カレンダー: 予定の作成・変更・削除、✅ の付け外し、失敗してもTodoが保存されること
- LINE通知: 今日・明日・期限切れの選び方、完了済みの除外、対象なし、重複防止、認証失敗、LINE API の失敗
